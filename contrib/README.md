# contrib

The modules `require` loads. Each directory is one module, named as you
`require` it, with a README. What each one is for, in one line apiece:
[Extensions](../docs/extensions.md#modules).

Libraries for your programs:

- Common Lisp compatibility: `dotcl-thread`, `dotcl-socket`, `dotcl-gray`,
  `dotcl-float`, `dotcl-rotate-byte`, `dotcl-simd`
- The REPL and editors: `dotcl-repl`, `dotcl-code-info`, `dotcl-lsp`,
  `dotcl-lsp-coalton`
- .NET: `dotnet-class`, `dotnet-ffi`, `dotnet-nuget`, `asdf-nuget`,
  `dotnet-cs`

Under socket libraries such as usocket, not for direct use:
`dotcl-bsd-sockets`. Under `dotcl-dap` and `dotcl-lsp`: `dotcl-jsonrpc`.

Experimental: `dotcl-lock`, loading two versions of one system with a
lock file; `asdf-version-range`, version ranges in `:version`
dependencies; `asdf-parallel`, compiling the files of a build on several
threads; `asdf-extra-deps`, adding the dependencies a system forgot to
declare, and finding them.

Development tools, for looking inside a running process from the REPL:
`dotcl-advice`, `dotcl-clrmd`, `dotcl-dap`, `dotcl-decompiler`,
`dotcl-jitdisasm`.

`asdf` and `quicklisp` are generated by the build from their upstream sources
and are not kept here.

A module that REQUIREs another when it loads lists it in its `.asd`
(`:depends-on`). A published application carries only the modules its
build's manifest names, and the manifest learns about a module's own
dependencies from there.
